# Data Viz Posts

Create copy that helps readers understand one evidence-backed takeaway,
without repeating the visualization or overstating it.

## Gather the essentials

Extract them from the supplied material, then ask only for genuinely
missing items: data and source, chart type, axes/units/time range, main
finding, audience, and platform. For Pollitik work, use only the
provided or validated dataset and name limitations that materially affect
interpretation. Never invent a trend, a source, an interaction claim, or
a causal explanation.

If a Pollitik style guide, X account link, Substack link, or past posts
are supplied, read them before drafting and use them as style evidence.
Do not claim to have analysed interaction or view performance if those
metrics are not available.

## Drafting rules

1. Choose one takeaway. Cut facts that do not support it.
2. Use this narrative order when space permits: hook, context, reading
   guide, finding with one or two numbers, then implication or caveat.
3. State each fact once. Before finalizing, give every sentence one job;
   merge or remove sentences with the same job.
4. Explain chart encodings once, only when they are not obvious. Do not
   narrate visible details without adding meaning.
5. Use a direct, human voice. Do not use em dashes, hype, filler, or
   unsupported causality. Mention uncertainty briefly when it changes
   the conclusion.

## Platform outputs

Read [platform-formats.md](references/platform-formats.md) for platform
lengths, alt text, tags, hashtags, scoring, and examples. Return the
copy first, ready to paste. Then provide a brief editor note: takeaway,
audience, redundancy cuts, score, and any caveat or missing input.

## Tags and hashtags

Ask whether there are relevant organisations, authors, or datasets the
user is permitted to tag. Suggest only directly relevant verified
accounts, never tag unrelated high-reach accounts. Use zero to two
specific hashtags, and omit them when they add no discovery value.

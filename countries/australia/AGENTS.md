# AGENTS.md — Australia PM approval assignment

Narrows the root `AGENTS.md` and `CLAUDE.md` to this one assignment. It
adds nothing that contradicts them and duplicates none of their rules —
if something isn't covered here, the repo-wide rules apply unmodified.

This workspace was originally generated by `python/init_country_workspace.py`
as a skeleton (see `docs/country_blueprint.md`, the Canada blueprint).
The scope, reference profile, country Skill, and reference data below
have since been resolved from real Australia data — the tracked
snapshot (`countries/australia/data/australia_reference_snapshot.csv`),
the EAD Series/Question Wording workbook, and (for the Prime Minister
officeholder timeline) Wikipedia used as a discovery aid only, plus one
directly-retrieved authoritative government source. **The Morrison ->
Albanese transition (2022-05-23) is government-source VERIFIED** — on
2026-08-25 the user approved four authoritative Australian
government/parliamentary domains (`aph.gov.au`, `pm.gov.au`,
`gg.gov.au`, `naa.gov.au`, now in `config/allowed_domains.txt`), and
`https://www.pm.gov.au/about-prime-minister` was successfully retrieved
and directly quotes the exact date. Two further domains named by the
user as corroborating this (`gg.gov.au`, `aph.gov.au`) could not be
retrieved this session (timeout / HTTP 403) and are recorded as
user-supplied corroboration only, not independently-verified provenance.
**Every other officeholder date remains UNVERIFIED** — this pass
deliberately did not repeat blocked-page attempts for older Prime
Ministers (see the reference profile's attempt log). No date was
changed from its Wikipedia-discovered candidate value; only provenance
status changed. No Canada blueprint data, series, pollsters, sources, or
results were copied in.

## Scope

Australian **Prime Minister** individual approval/support only — job
approval, job satisfaction, overall performance, favorable/unfavorable
opinion, positive/negative image, general approval/sympathy, as the
office-holder personally. Not the Government as a whole, and not a
generic "leadership of this country" measure unless the question
wording confirms it targets the PM.

**Excluded** (route anything that looks like these to REVIEW or skip it,
never coerce it into a PM series):
- Government-as-a-whole approval — `CSES`, whose EAD question wording
  explicitly branches to "the government in [CAPITAL]" or "the
  president," not the Prime Minister.
- Issue-specific approval (economy, immigration, healthcare, etc.)
- Vote-intention / preferred-PM / head-to-head leader-preference
  questions
- Continuous 1-10 / 1-100 grading scales
- Trust/confidence in the PM (no Australia exception currently exists in
  `config/country_rules.yaml`)

**Requires human/research verification before treating as in- or
out-of-scope** (see the reference profile for exact reasoning):
`FOX&HEDGEHOG` (EAD Description is an unresolved internal placeholder),
`FreshwaterStrategy` / `Freshwater Strategy` (generic multi-figure
favorability battery, PM-target not confirmed by wording alone),
`GALLUPWORLD_LSHP` / `GALLUPWORLD_LDR` (international "leadership of
this country" programs, PM-target not independently confirmed).

## Research rules for this assignment

- Approved domains only: `config/allowed_domains.txt`. Never fetch
  outside this list, never route around it. Of the domains already
  approved there, `pollbludger.net`, `morningconsult.com`,
  `pro.morningconsult.com`, `ipsos.com`, `docs.google.com`,
  `drive.google.com`, `archive.ph`, and `statista.com` are the ones
  already observed in Australia's existing Source-column data (see the
  reference profile's "Approved-source domains" section for the full
  derivation). Several other domains that appear in Australia's
  *historical* (pre-2024) data — e.g. `roymorgan.com`,
  `essentialvision.com.au`, `essentialreport.com.au`, `theage.com.au`,
  `theguardian.com`, `angus-reid.com`, `analyticscampus.gallup.com`,
  `newspoll.com.au` — are **not** currently approved (they pre-date the
  2024-01-01 cutoff documented in `config/allowed_domains.txt`'s own
  header) and must not be fetched without explicit new approval, even
  though the historical data point already sitting in the snapshot is
  fine to reference as existing data.
- Prefer the original polling firm's own site over an aggregator or
  secondary write-up when both are approved domains.
- **One researcher pass per source batch when possible** — hand the
  researcher agent a batch of candidate URLs/date-ranges for one
  pollster/domain at a time, not one agent call per individual poll.
- Preserve exactly what's retrieved, never paraphrase or invent:
  source URL, question wording, fieldwork dates, sample size, and the
  reported positive/neutral/negative values.
- **Deduplicate before the matcher** — if a batch retrieval turns up the
  same poll wave twice (same pollster, same fieldwork dates, same
  values), resolve that before candidates reach the matcher agent, not
  after.
- **Batch candidates to the matcher and to the validator** — pass a
  batch of extracted candidates through matcher/validator together
  (`python/validate_record.py`/`python/stage_changes.py` both support
  batch input) rather than one candidate per invocation.
- Any uncertain series match, unresolved wording, or inferred field
  (e.g. sample size inferred from a firm's known pattern rather than
  stated outright) routes to REVIEW. Never guess it into APPROVED. This
  includes every series in the reference profile's "requires
  verification" table.
- **Never assign a leader from series recency.** Resolve
  `executive_name` from the officeholder timeline in australia.md
  against the observation's own Date — never because a series "looks
  recent." Only the Morrison -> Albanese boundary (2022-05-23) is
  government-source verified (via `pm.gov.au`); every other date is
  still UNVERIFIED — do not describe a leader assignment made from an
  unverified row as "verified."

## Deterministic result routing — never inferred

Which file answers "the APPROVED Australia dataset" (a fresh local
run's output, or a future tracked worked-example snapshot) is decided
by `python/resolve_assignment_dataset.py`, not by Codex's judgment:

```
python python/resolve_assignment_dataset.py --country Australia --purpose approved
python python/resolve_assignment_dataset.py --country Australia --purpose review
```

Until a local research run has actually happened in this workspace and
`countries/australia/data/australia_assignment1_approved.csv` /
`..._review.csv` exist, this resolver has nothing to return for
Australia — report that plainly (no local run yet, no tracked
worked-example yet) rather than guessing or fabricating a dataset.
`australia_reference_snapshot.csv` is never a candidate output of this
script either way — it has no code path that can return it. Reference/
duplicate lookup is a completely separate tool
(`python/reference_lookup.py` against the DuckDB index built from the
snapshot) and never goes through this resolver.
